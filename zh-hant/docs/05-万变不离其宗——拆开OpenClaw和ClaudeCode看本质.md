## 📖 第一小節：先看這兩個產品——生活管家和編程搭檔

### ❓ 提問

> 一個幫你處理生活瑣事，一個幫你寫代碼——它們能是一回事嗎？

### 🦞 OpenClaw：你的生活管家

想象你有個AI管家，每天早上幫你：
- 查今天的天氣和日程
- 給重要的人發提醒
- 整理你下載的文件
- 回覆一些簡單郵件

你只需要説："幫我安排今天的行程，如果下雨就取消户外活動。"

它會自己查天氣、看日曆、發消息——**一氣呵成，很少停下來問你**。

### 💻 Claude Code：你的編程搭檔

再想象你在寫代碼，有個AI搭檔：
- 你説"把這個函數改成異步的"
- 它先給你看它打算怎麼改
- 你點頭，它才真正動手
- 改完自動跑測試，沒過就繼續改

每一步都給你看、等你確認——**寧可慢一點，也不能改錯**。

### 🤔 表面看，完全不同

| | OpenClaw | Claude Code |
|:---|:---|:---|
| 面對的場景 | 生活瑣事 | 編程開發 |
| 工作方式 | 一氣呵成 | 步步確認 |
| 出錯成本 | 發錯郵件能改 | 刪錯代碼難恢復 |
| 給你的感覺 | 像管家，充分授權 | 像搭檔，謹慎小心 |

**看起來，這完全是兩類產品。**

但等等——第四章説的八部件，它們身上有嗎？

## 📖 第二小節：拆開看——原來都是八部件

### 💡 揭曉答案

它們不僅有，而且**一模一樣**。

```
        八部件框架（同一套骨架）
        ┌─────────────────────────────────────┐
        │  🧠 核心大腦（大模型做判斷）          │
        │  🎯 目標（你要它做什麼）              │
        │  📋 上下文（它能看到什麼）            │
        │  🧠 記憶（它記得什麼）                │
        │  🛠️ 工具（它能調用什麼）              │
        │  🔒 邊界（什麼能做不能做）            │
        │  👁️ 觀測（怎麼知道做對了）            │
        │  🔄 循環（怎麼一步步推進）            │
        └─────────────────────────────────────┘
                 │            │
                 ▼            ▼
           ┌──────────┐  ┌──────────┐
           │ OpenClaw │  │ClaudeCode│
           │ 生活場景 │  │ 代碼場景 │
           └──────────┘  └──────────┘
```

### 📊 兩個產品的八部件

| 部件 | OpenClaw | Claude Code |
|:---:|:---|:---|
| 🧠 **核心大腦** | GPT-5 / Claude 4 | Claude 4.6 |
| 🎯 **目標** | "查天氣並提醒朋友" | "把這個函數改成異步" |
| 📋 **上下文** | 天氣、日程、聯繫人 | 代碼文件、項目結構 |
| 🧠 **記憶** | 你的習慣、常用郵箱 | 項目配置、構建命令 |
| 🛠️ **工具** | 瀏覽器、郵件、通訊錄 | 文件讀寫、Bash、測試 |
| 🔒 **邊界** | 寬鬆，充分授權 | 嚴格，危險操作需確認 |
| 👁️ **觀測** | 執行結果直接返回，快速推進 | 測試通過才繼續，嚴格驗證 |
| 🔄 **循環** | 快速循環，一氣呵成 | 步步確認，謹慎推進 |

---

> 💡 **關鍵發現**：八部件都有，只是每個部件的"內容"不同——就像同樣的劇本，不同的演員演出來完全不同。

> 💡 **補充説明**： OpenClaw 和 Claude Code 都有觀測和循環，只是配置不同——OpenClaw 觀測簡單結果快速推進，Claude Code 通過測試嚴格驗證才繼續。這體現了同樣的八部件，配置不同，行為完全不同。

## 📖 第三小節：學會這套透視法——看透任何 AI 產品

### ❓ 提問

> 搞懂了OpenClaw和Claude Code都是八部件，但這有什麼用？  
> 下次遇到通義千問、豆包、DeepSeek，或者某個新出的AI產品，我該怎麼快速理解它？

### 📝 術語

- **八部件透視法**：用"核心大腦、目標、上下文、記憶、工具、邊界、觀測、循環"八個維度分析任何Agent產品的快速方法

### 💬 一句話解釋

> 💡 **八部件框架就像一副透視鏡——不管AI產品包裝得多花哨，用它一看，就知道這產品的"骨架"長什麼樣。**

### 🧐 你可以先這樣理解

前兩節我們拆開OpenClaw和Claude Code，發現它們都是八部件。但這只是**開始**——真正有用的是，你能用這套框架去看**任何**AI產品。

就像學會了看房子的"户型圖"：
- 不管裝修風格是現代還是復古，户型圖一看就知道幾室幾廳
- 八部件就是AI產品的"户型圖"

### 📚 八部件透視法怎麼用

遇到任何AI產品，問這八個問題：

| 問題 | 你在看什麼 | 例子：通義千問 | 例子：豆包 |
|:---|:---|:---|:---|
| **1. 核心大腦是什麼？** | 底層用的大模型 | 自研大模型 | 字節大模型 |
| **2. 目標怎麼定？** | 它擅長什麼類型任務 | 辦公寫作、文檔處理 | 內容創作、聊天 |
| **3. 上下文裝什麼？** | 能記住多少、記什麼 | 多輪對話+上傳文檔 | 聊天記錄為主 |
| **4. 記憶怎麼存？** | 長期記憶有沒有、存在哪 | 雲端同步 | 賬號關聯 |
| **5. 有什麼工具、邊界在哪？** | 能調什麼能力、限制是什麼 | 搜索、畫圖、代碼解釋 | 搜索、寫作輔助 |
| **6. 觀測怎麼做？** | 怎麼獲取執行結果 | 搜索返回結果 | 對話響應 |
| **7. 循環怎麼跑？** | 一輪對話還是多輪迭代 | 單輪為主，複雜任務多輪 | 對話式連續 |
| **8. 整體配合怎樣？** | 八個部件協同是否順暢 | 各部件配合成熟 | 側重對話場景 |

**你不用深入研究每個答案**——只要大概知道這八樣東西在哪，這產品的"脾氣"你就摸清了。

### 📚 實戰演練：快速掃描三個產品

用八部件框架，我們快速"掃描"一下市面上的產品：

**通義千問（阿里）**
- 核心大腦：自研大模型，辦公場景優化
- 上下文：支持超長文檔、多輪對話
- 工具：搜索、畫圖、代碼解釋、PPT生成
- 特點：工具豐富，適合辦公場景

**豆包（字節）**
- 核心大腦：字節大模型，內容創作優化
- 上下文：對話連貫性好
- 工具：搜索、寫作、圖片生成
- 特點：對話自然，適合內容創作

**DeepSeek**
- 核心大腦：推理能力強，代碼場景優化
- 上下文：支持長文本、代碼理解
- 工具：代碼執行、搜索
- 特點：代碼和推理任務表現好

**你會發現**：每個產品都在八部件的框架裏"做文章"，只是側重點不同。

### ✅ 你只需要記住

1. **八部件是透視鏡**——不管產品包裝成什麼樣，用它一看就懂骨架
2. **問八個問題就夠了**——大腦、目標、上下文、記憶、工具、邊界、觀測、循環
3. **比較產品時看配置**——不是看宣傳語，看八部件分別怎麼配的
