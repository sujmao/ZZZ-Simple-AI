
# 🧠 第三章 大模型派與駕馭工程派：一體兩面的雙螺旋

## 🤔 讀前先想

## 🧬 先看兩種思路——一體兩面的雙螺旋

| 思路 | 它更看重什麼 | 你可以先怎麼理解 |
| --- | --- | --- |
| 🧠 **大模型派（Big Model）** | 模型本身是不是越來越強 | 更相信"腦子"會越來越強 |
| 🛠️ **駕馭工程派（Harness Engineering）** | 模型外部的系統是不是足夠穩 | 更相信"系統"要先把模型的輸出穩穩地承接住 |

> 💡 **一句話總結**：AI 要真正解決問題，既需要模型能力進化，也需要外部系統把這股能力組織起來——**兩者不是對立，而是像 DNA 雙螺旋一樣，並行發展、相互纏繞、缺一不可**。

## 📖 第一小節：為什麼會有這兩種做法

### ❓ 提問

- 為什麼同樣做 AI，最後會分出兩種關注點？
- 為什麼只談模型或者只談系統，都不夠解釋真實產品？

### 📝 術語

| 項目 | 內容 |
|:---|:---|
| **中文** | 兩條主線 |
| **英文** | Two Approaches |
| **補充** | 指大模型派（Big Model）和駕馭工程派（Harness Engineering）兩種不同的側重點 |

### 💬 一句話解釋

> 💡 **説白了，做 AI 產品時會遇到兩類不同的問題：一類靠模型變強解決，一類靠系統設計解決，所以自然分出了兩條思路。**

### 🧐 你可以先這樣理解

想象你在搭一輛賽車：

- 🏎️ **大模型派**更關心：發動機能不能更強勁？馬力能不能更大？
- 🔧 **駕馭工程派**更關心：結構是否穩定？制動是否靈敏？抓地是否牢固？

**這不是二選一，而是必須同時做好。** 光有好發動機，車會散架；光有好車架，跑不快。

更重要的是，這兩者是**相互促進**的：
- 發動機越強，對車架的要求越高，推動車架技術進化
- 車架越穩，越能承受更強發動機的輸出，讓發動機有用武之地

所以這不是純理論爭論，也不是路線之爭，而是做產品時必然會遇到的兩類互補問題。

### 📖 示例

面對同一個需求，兩類人會先問不同的問題：

**大模型派先問**：
> "模型能不能自己把複雜任務一次性想明白？"

**駕馭工程派先問**：
> "就算模型會想，知識庫、工具、權限和審計誰來接？"

這兩個問題的出發點不同，就會自然走向兩種不同的側重。

### ✅ 你只需要記住

- 🎭 這不是純理論爭論，而是做產品時自然出現的兩種思路
- 🧠 一種更強調模型進化，一種更強調系統組織
- 🎯 兩條路不是對立的，而是缺一不可

---

### 📖 具體案例：看產品怎麼站隊

理論説得再多，不如看真實產品怎麼選擇。

| 產品/技術 | 更偏向哪派 | 怎麼看出來的 |
|:---|:---|:---|
| **DeepSeek-R1 / Kimi k2.5** | 🧠 大模型派 | 強調模型自己推理、規劃，減少外部干預 |
| **釦子 Coze / Dify** | 🛠️ 駕馭工程派 | 提供大量外部工具、流程框架、RAG組件 |
| **ChatGPT / Claude** | 兩者融合 | 既有強模型，又有完善的系統層設計 |

**洞察**：沒有產品"純粹"屬於某一派，只是**側重點不同**。真正成熟的產品，往往是兩派的融合。

## 📖 第二小節：大模型派——相信腦子夠強，事情自然成

### ❓ 提問

- 為什麼隨着模型越來越強，會有人想把更多事情直接交給模型本身？
- 為什麼這一派會覺得很多外部補丁以後可能變輕？

### 📝 術語

- **中文**：大模型派
- **英文**：Big Model
- **補充**：更強調模型本身持續變強的思路

### 💬 一句話解釋

> 💡 **説白了，大模型派相信：只要"腦子"夠強，很多原來需要外部補的能力，以後可以交給模型自己搞定。**

### 🧐 你可以先這樣理解

如果模型的理解能力、推理能力和長上下文處理能力不斷增強，會發生什麼？

- ✅ 一些原來很依賴外部技巧的做法，可能會變輕，甚至被模型吸收
- ✅ 一些複雜的提示詞工程，可能變得沒那麼必要
- ✅ 一些原來必須拆成多步驟的任務，模型可能一次性就能做好

這條思路更關心的是：**模型本身能不能做得更多、更穩、更聰明**。

它的基本判斷是，很多複雜度最終可以往模型內部收。

### 📖 示例

更強的模型可能帶來這些變化：

| 原來需要外部補的 | 模型變強後可能的變化 |
| --- | --- |
| 很細碎的提示詞技巧 | 模型更能直接理解自然語言意圖 |
| 複雜的多步驟拆解 | 模型更能自己規劃步驟 |
| 大量的示例（Few-shot） | 模型更能從簡單描述裏舉一反三 |
| 固定的工具調用格式 | 模型更能靈活決定何時用、怎麼用 |

---

### 📖 行業發展：大模型派的實際突破

技術發展從來不是單方向的。當我們關注"駕馭工程派"如何搭建外部系統時，**大模型本身也在快速進化**，不斷把原來需要外部技巧的能力"收"進模型內部。

**案例 1：思考鏈（Chain-of-Thought, CoT）的演進**

| 階段 | 做法 | 變化 |
| :--- | :--- | :--- |
| 早期 | 人必須在提示詞裏寫"讓我們一步步思考" | 靠外部技巧引導 |
| GPT-4 時代 | 模型開始能自動展示推理過程 | 模型自己學會"慢思考" |
| DeepSeek-R1 / Kimi k2.5 | 模型內置強大的推理能力，自動拆解複雜問題 | **推理成為模型原生能力** |

---

> 💡 **關鍵洞察**：從"人教模型怎麼思考"到"模型自己學會思考"——**複雜度從外部技巧轉移到了模型內部**。

**案例 2：工具調用能力的增強**

| 階段 | 做法 | 變化 |
| :--- | :--- | :--- |
| 早期 | 必須用固定格式（如 JSON）告訴模型何時調用工具 | 嚴格的外部協議 |
| GPT-4 / Claude 3 | 模型能更自然地理解工具用途，調用更靈活 | 理解能力增強 |
| 最新模型 | 模型能自主決定調用時機、參數調整，甚至錯誤修正 | **工具使用越來越像本能** |

---

> 💡 **關鍵洞察**：模型不再需要"被精確指揮"才能使用工具，而是**越來越能自主判斷**。

**案例 3：長上下文處理的飛躍**

| 階段 | 上下文長度 | 能力邊界 |
| :--- | :--- | :--- |
| GPT-3 時代 | 2K-4K tokens | 只能處理短文 |
| GPT-4 / Claude 2 | 32K-100K tokens | 能讀長文檔 |
| GPT-4o / Claude 3 | 128K-200K tokens | 能讀整本書、大量代碼庫 |
| Gemini 1.5 Pro / Kimi K2.5 | **1M+ tokens（一兆）** | 能讀整本長篇小説、海量代碼庫、長視頻內容 |

---

> 💡 **關鍵洞察**：上下文窗口的擴展，讓模型能**一次性處理更復雜的任務**，減少了對"分段處理"等外部技巧的依賴。

> 💡 **案例 4和5（多模態能力、代碼能力）**：模型還在持續進化，從"能讀文字"到"能看懂聽懂"，從"能寫代碼"到"理解軟件工程"——核心趨勢是**專業能力不斷內化為模型能力**。

---

### 🔄 雙向演進：行業真相

> **大模型派和駕馭工程派不是誰在取代誰，而是雙線並行、相互刺激。**

- 模型變強了 → 對系統的要求更高（需要承接更強的能力）
- 系統做穩了 → 能釋放模型更多潛力（讓模型有用武之地）

這就是"雙螺旋"的真實寫照。

### ✅ 你只需要記住

- 🧠 大模型派更看重模型能力本身的進化
- 📈 它相信"腦子變強"會帶來整體能力提升
- 🎯 很多複雜度最終可以往模型內部收

---

💭 **剛才我們看了大模型派的主張**——相信模型自己會越變越強。但就算模型再聰明，也有很多事是它做不到的——比如真的去發郵件、查日曆，或者做權限控制。這就引出了另一種思路：與其等模型變強，不如先把系統搭好。

## 📖 第三小節：駕馭工程派——模型再聰明，也得有系統託底

### ❓ 提問

- 為什麼就算模型繼續變強，很多團隊還是會堅持先把系統做穩？
- 為什麼真實工作裏，模型本身不等於知識、工具、權限和流程？

### 📝 術語

- **中文**：駕馭工程派
- **英文**：Harness Engineering
- **補充**：更強調模型外部系統組織能力的思路

### 💬 一句話解釋

> 💡 **説白了，駕馭工程派相信：模型能力要真正落地，關鍵還在於模型外部的系統設計。**

### 🧐 你可以先這樣理解

模型再強，也有它做不到的事：

- ❌ 模型本身不會自己接企業知識庫
- ❌ 模型本身不會真正執行工具（發郵件、查日曆、操作數據庫）
- ❌ 模型本身不等於權限控制、驗證機制、審計流程

所以要讓 AI 在真實工作裏穩定做事，還需要**外部系統**把信息、工具、流程和約束組織起來。

這條思路的核心是：**先讓系統穩穩地承接住模型的能力，再妥善地組織好、用起來**。

### 📖 示例

這些都需要系統層的設計：

| 系統層能力 | 為什麼重要 |
| --- | --- |
| 🔌 知識庫接入 | 把公司文檔、實時信息接到模型上下文裏 |
| 🛠️ 工具執行 | 真正去發郵件、查日曆、操作數據庫 |
| 🔒 權限控制 | 哪些操作需要審批，哪些可以自動執行 |
| 📝 審計日誌 | 模型做了什麼，要能追溯、能覆盤 |
| ⚠️ 風險確認 | 高風險動作前停下來等人確認 |

### ✅ 你只需要記住

- 🛠️ 這條思路更看重系統設計
- 🎯 它相信"系統做穩"是 AI 真正落地的關鍵
- 🔒 模型本身不等於權限、驗證、審計和執行層

---

💭 **剛才我們分別看了兩派的核心主張**：大模型派相信模型自己會越變越強，駕馭工程派相信系統才能把能力穩穩接住。現在問題來了——前兩章學過的那些技術，到底哪些更偏模型、哪些更偏系統？

### 🧐 把技術放回兩條路里看

| 技術 | 更偏向哪條路 | 為什麼 |
| :--- | :---: | :--- |
| 🔍 檢索增強生成（RAG） | 🛠️ 駕馭工程派 | 它通過外部檢索給模型補資料 |
| 🛠️ 工具調用（Tool Calling） | 🛠️ 駕馭工程派 | 真正執行工具的是外層應用，不是模型本身 |
| 📋 工作流（Workflow） | 🛠️ 駕馭工程派 | 它先用外部流程把步驟固定下來，確保穩定性 |
| 🤖 智能體（Agent） | 🧠🛠️ 兩邊都重要 | 一邊依賴更強模型，一邊依賴更完整的系統組織 |
| 📦 技能（Skill） | 🛠️ 駕馭工程派 | 它把常用做法提前整理成可複用的任務包 |

**這樣看的好處**：同一個技術名字，背後往往更偏向某一類問題。放回兩條主線裏，整套知識會更成體系。

### 🧩 核心洞察：模型進化 vs 系統承接

AI 產品設計的核心問題始終是——

> **模型能力在進化，但永遠有不確定性；系統需要承接這種能力，同時控制風險。**

這不是"二選一"的問題，而是**必須同時做好**的問題：
- 只有模型沒有系統 → 能力無法落地，風險不可控
- 只有系統沒有模型 → 缺乏智能內核，變成傳統軟件

**雙螺旋的本質**：
- 模型越強 → 對系統要求越高 → 推動系統進化
- 系統越穩 → 越能釋放模型潛力 → 讓模型有用武之地

---

### 🔭 趨勢展望：什麼會消失，什麼會留下

模型變強了，是不是很多外部設計就沒必要了？

**不是所有外部能力都一樣**，可以分為兩類：

| 類型 | 特徵 | 未來趨勢 |
| :--- | :--- | :--- |
| 🩹 **臨時補丁** | 只是因為舊模型不夠強才存在 | 會逐漸簡化 |
| 🏗️ **系統層能力** | 無論模型多強都必須保留 | 長期存在 |

**臨時補丁的例子**：
- 過細的提示詞技巧
- 僵化的步驟拆分
- 大量的示例樣本

**系統層能力的例子**：
- 工具執行層（真正操作外部系統）
- 權限控制、驗證機制、審計日誌
- 業務規則和約束條件

**關鍵洞察**：

> 模型變強後，**為彌補舊模型短板而存在的設計會簡化**，但**負責組織模型能力、確保穩定落地的系統層能力不會消失**。

### 📖 自己動手：分析你用的產品

**實驗任務**：判斷你常用的 AI 產品更偏向哪一派

**步驟**：
1. 選一個你常用的 AI 產品
2. 回答以下問題：
   - **產品做什麼？** （生成內容？執行任務？輔助決策？）
   - **模型做什麼？** （直接生成結果？提供建議？規劃步驟？）
   - **系統做什麼？** （檢索資料？調用工具？控制流程？驗證結果？）
   - **如果模型突然失靈，產品還能用嗎？** （能 → 偏工程派；不能 → 偏模型派）
3. 判斷它更偏向哪一派，並説明理由

**案例分析框架**：

| 維度 | 大模型派特徵 | 駕馭工程派特徵 |
| :--- | :--- | :--- |
| 產品核心 | 模型輸出就是產品 | 模型只是組件之一 |
| 失敗表現 | 模型錯了，產品就錯了 | 模型錯了，系統能兜底 |
| 技術重點 | 提示工程、微調 | 工具集成、流程設計、權限控制 |

**思考問題**：
- 這個產品為什麼選擇這種側重？
- 它的場景更適合哪種策略？
- 如果讓你改進，你會加強哪一派的能力？

---

### 🌉 為下一章鋪墊

明白了大模型派和駕馭工程派是相輔相成的雙螺旋，下一個問題自然來了：

**智能體（Agent）這個產品形態，是怎麼把這兩條主線融合在一起的？**

它既需要強大的模型能力（大模型派），也需要完善的系統設計（駕馭工程派）。一個真正好用的智能體，必須同時做好兩者——它是兩條主線交匯的**結晶點**。

這就是下一章要聊的：**智能體是怎麼"幹活"的**——我們會看到，八部件框架如何同時體現兩派的思想。
