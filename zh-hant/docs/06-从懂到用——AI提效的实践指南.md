## 📖 第一小節：選工具——別選最強的，選最配的

### ❓ 提問

> 市面上AI工具這麼多，我怎麼知道哪個適合我？  
> 是不是選功能最全、模型最強的就對了？

### 💬 一句話理解

> 選工具不是選"最強"的，是選"最配你場景"的。

### 🧐 你可以先這樣理解

想象你要買一雙鞋：
- 跑步鞋很強，但如果你要爬山，不如登山鞋合適
- 八部件框架就是你的"試鞋清單"——幫你判斷這雙鞋合不合腳

用八部件評估一個AI工具，問自己這八個問題：

| 問題 | 為什麼重要 |
|:---|:---|
| 它用的什麼模型？適合我的任務嗎？ | 複雜任務需要強模型，簡單任務普通模型就夠 |
| 它能記住多少上下文？ | 長文檔分析需要大上下文，日常聊天不需要 |
| 它能調用我需要的工具嗎？ | 辦公場景需要文檔/郵件工具，編程場景需要代碼工具 |
| 錯了怎麼辦？有確認機制嗎？ | 高風險任務需要嚴格邊界，低風險任務可以更開放 |
| 我怎麼知道做得對不對？ | 需要明確驗收標準才能判斷輸出質量 |
| 工作節奏適合我嗎？ | 緊急任務要快，複雜任務要穩 |

> **不是看哪個分數高，是看哪個在你最在乎的維度上得分高。**

---

### 📚 快速決策法

| 如果你主要做... | 重點看什麼 | 選擇方向 |
|:---|:---|:---|
| **一次性簡單任務** | 上手快不快 | WorkBuddy、通義千問、豆包 |
| **重複性工作** | 能不能保存套路 | 支持Skill的工具 |
| **高風險任務** | 有沒有確認機制 | CodeBuddy、Claude Code |
| **編程開發** | 工具全不全 | CodeBuddy、Cursor、Trae |

### ✅ 你只需要記住

1. **沒有最好的工具，只有最合適的工具**
2. **用八部件框架快速評估，別被宣傳語迷惑**
3. **先試用，再決定——實踐出真知**

## 📖 第二小節：用工具——出問題先檢查這三樣

### ❓ 提問

> AI輸出不對，是模型不行，還是我用得不對？  
> 怎麼排查問題出在哪？

### 💬 一句話理解

> 80%的問題不出在模型，出在你沒把任務説清楚——先檢查目標、上下文、邊界。

### 🧐 你可以先這樣理解

AI就像一位新入職的實習生：
- 你説"寫個報告"——他不知道寫什麼報告、給誰看、多長
- 你説"寫個報告"，加上"關於Q3銷售數據的，給總經理看的，一頁紙"——他就明白了

> **三板斧排查法**

---

**第一板斧：目標説清楚了嗎？**
```
❌ 模糊："分析這個數據"
✅ 清楚："分析這個銷售數據，找出Q3比Q2下降的原因"
```

**第二板斧：上下文給夠了嗎？**
```
❌ 不足：直接問"怎麼改進？"
✅ 充分："背景是...目標是...限制條件是..."
```

**第三板斧：邊界設了嗎？**
```
❌ 開放："隨便寫"
✅ 約束："500字以內，用大白話，別説專業術語"
```

### 📚 常見問題和排查

| 問題表現 | 最可能原因 | 怎麼解決 |
|:---|:---|:---|
| AI理解錯了方向 | 目標沒説清 | 用"你要做的是...目的是..."重新描述 |
| AI漏了重要信息 | 上下文不夠 | 把相關背景、數據、文件傳給它 |
| AI輸出太長/太短 | 邊界沒設 | 明確字數、格式、風格要求 |
| AI用了錯誤的方法 | 工具説明不清 | 告訴它"用XX方法，不要YY方法" |

### ✅ 你只需要記住

1. **先檢查自己的輸入，再懷疑模型能力**
2. **目標、上下文、邊界——這三樣搞定，80%問題沒了**
3. **從小任務開始，逐步積累經驗**

## 📖 第三小節：沉澱經驗——從每次教到一次封裝

### ❓ 提問

> 為什麼我教AI做一件事，下次還要重新教？  
> 有沒有辦法讓它記住我的套路？

### 📝 術語

- **Skill**：任務目標 + 上下文模板 + 執行步驟 + 驗收標準的封裝

### 💬 一句話理解

> Skill就是把"你怎麼教AI做這件事"的經驗，保存下來下次直接用。

### 🧐 你可以先這樣理解

想象你每週都要寫週報：
- **第一次**：告訴AI"幫我寫週報，包含本週完成、下週計劃、遇到的問題"
- **第二次**：又要説一遍...
- **第N次**：每次重複，很煩

Skill就是把這個過程**封裝**下來：
- 固定格式是什麼
- 需要哪些輸入信息
- 輸出應該長什麼樣
- 怎麼算好、怎麼算不好

封裝好以後，以後只説"用週報Skill"，AI就知道整套流程。

### 📚 Skill封裝示例：週報生成器

**你不需要手寫模板**——只要帶着AI走一遍，它就能自動總結。

**一次完整的封裝過程**：

```
你：幫我寫週報，要包含本週完成、下週計劃、遇到的問題
（AI生成初稿）

你：不對，格式應該是"完成事項→數據亮點→遇到的問題"
（AI調整）

你：還有，下次記得先問我要數據，別自己編
（AI記錄偏好）

AI：我總結了這個流程，包含目標、輸入、步驟和格式。
     要保存為Skill嗎？以後可以直接調用。
     
你：保存，叫"週報生成器"
```

**AI自動生成的Skill包含**：
- 觸發條件（什麼時候用）
- 需要的信息（輸入）
- 執行步驟（怎麼做）
- 輸出格式（長什麼樣）

**主流工具都支持**：WorkBuddy、CodeBuddy、通義千問等都可以保存個人Skill/智能體

### ✅ 你只需要記住

1. **Skill = 你的經驗 + AI的執行能力**
2. **不需要手寫模板——帶着AI走一遍，它自動幫你封裝**
3. **從重複最多的任務開始，邊用邊沉澱**

## 📖 第四小節：站在巨人的肩膀上——先用現成的 Skill

### ❓ 提問

> 每次都要自己封裝Skill嗎？  
> 有沒有別人已經封裝好的可以直接用？

### 💬 一句話理解

> 大多數常見任務，早就有人封裝好了——先找現成的，沒有才自己造。

### 🧐 你可以先這樣理解

Skill生態正在快速發展，就像手機App商店一樣：
- **通用任務**：寫週報、回郵件、整理數據...早就有成熟方案
- **行業專用**：代碼審查、財務分析、客服話術...各個領域都有
- **個人定製**：只有你自己獨特的 workflow 才需要自己封裝

**為什麼要先用現成的？**

> 1. **省時間**：不用從零摸索
> 2. **質量高**：別人已經迭代優化過  
> 3. **學思路**：看看別人怎麼封裝，學習借鑑

### 📚 主流AI工具的Skill生態

| 工具 | Skill生態 | 如何使用別人的Skill |
|:---|:---|:---|
| **WorkBuddy** | Skills 市場 | 瀏覽市場 → 點擊"添加" → 直接調用 |
| **CodeBuddy** | CodeBuddy Skills | 導入 Skill 文件或從社區下載 |
| **通義千問** | 智能體市場 | 搜索場景 → 添加智能體 → 一鍵使用 |
| **Coze/釦子** | 插件+工作流市場 | 瀏覽插件 → 添加到自己的Bot |

**使用方式**：找到合適的Skill → 導入/添加 → 直接調用，不用從零開始

### 📚 Skill的複用方式

**方式一：使用"導入Skill"功能**

大部分AI工具支持導入外部Skill：
```
1. 從Skill市場/社區下載Skill文件（通常是 .json/.md/.yaml 格式）
2. 在AI工具中選擇"導入Skill"/"添加自定義Skill"
3. 選擇文件，完成導入
4. 以後直接調用這個Skill
```

**方式二：放入通用目錄，多工具共享**

更高級的方式——把Skill文件放在所有AI工具都能訪問的位置：
```
項目目錄
└── .agents/
    └── skills/
        ├── 週報生成器/
        │   └── SKILL.md
        ├── 郵件回覆助手/
        │   └── SKILL.md
        └── 代碼審查/
            └── SKILL.md
```

**支持 `.agents` 目錄的工具**：
- **CodeBuddy**：原生支持 `.agents/skills/`
- **OpenCode**：原生支持 `.agents/skills/`
- **Claude Code**：兼容 `.agents/skills/`

**好處**：
- 一次配置，多工具通用
- 團隊協作時，共享同一個Skill庫
- 備份方便，換工具時Skill不丟失

### 📚 找不到現成的怎麼辦？

如果市場上沒有合適的Skill，就自己封裝。方法在第3節講過：**帶着AI走一遍，它自動幫你總結形成標準化Skill**。

### 📚 選用 vs 自建的決策

| 場景 | 建議 | 原因 |
|:---|:---|:---|
| **常見通用任務**（週報、郵件、翻譯） | **先用現成的** | 別人優化過，質量有保障 |
| **行業專用任務**（代碼審查、財務分析） | **找行業Skill** | 可能有人分享過類似需求 |
| **個人獨特 workflow** | **自己封裝** | 只有你自己知道要什麼 |
| **敏感數據/特殊要求** | **自己封裝** | 控制權和隱私更有保障 |

### ✅ 你只需要記住

1. **大多數任務都有現成的Skill——先找再用**
2. **帶着AI走一遍，它能自動提煉Skill**
3. **從別人的Skill裏學習，再優化成自己的**
